# Changelog

Each release is a git tag. Under each version, "Projects" says what a project that follows the previous version should do.

## v1.1 (2026-11-19)

Feedback from the first project built to v1.0. New Must rules are marked **(new Must)**; changed ones **(changed Must)**.

- **Repo Practice Guide:**
  - A sixth principle, "The owner decides", and a section "Plans and decisions belong to the owner": a plan page per objective left empty for the owner **(new Must)**; open decisions listed on `open_questions.md` with their facts, with no options or recommendation unless asked **(new Must)**; no unrequested choices in code or pages **(new Must)**; a part that waits shows a status and a placeholder entry function **(new Must)**; `decisions.md` holds only owner decisions and technical choices, labelled **(changed Must)**; the protocol is logged and tagged `protocol-YYYY-MM-DD-<objective>` before the first result **(new Must)**.
  - Documentation: README.md is the canonical brief over any external copy **(new Must)**; the brief holds each objective's output and status **(changed Must)**; every number on a documentation page cites a committed script or table **(new Must)**; root configuration files share one grouped Map row **(changed Must)**; `open_questions.md`, `plan_<objective>.md` and an optional `guide_feedback.md` join the fixed pages; findings.md records dated discoveries and data_overview.md links to them; a decision may cite "this commit" until the next tag.
  - Inputs: a freeze or extract script may write a dated, unmodified subset of a clone into `data/<source>/<vintage>/`; nothing in data/ is edited by hand **(changed Must)**; every script-written vintage has a manifest.json that each load verifies **(new Must)**; extracts from a live clone check that nothing is newer than as_of **(new Must)**; the register names the generating code's repository and commit **(changed Must)**; hidden provenance folders are reviewed before freezing; a dev run on committed vintages defaults to the newest vintage **(changed Must)**; agreement rates cite their check-table row **(changed Must)**; method constants shared across parts live in `01_support/reference.R` **(new Must)**.
  - Outputs and running: results only a heavy environment can rebuild are committed once in `output/frozen/<protocol tag>/` **(new Must)**; community formats keep their file names; empty environment variables count as unset, and shell scripts read only the names and defaults settings() reads **(new Must)**; fig_\<name>.R may be a function file called by draw_\<part>(); a part page may list which output serves which question.
  - Reproducibility: renv with snapshot type "implicit" and renv/settings.json committed **(changed Must)**; the P3M URL takes the machine's codename **(changed Must)**; the first lock comes from a library the snapshot can restore **(new Must)**; setup warns when renv is not active **(new Must)**; a run manifest per entry point, with entry point, outputs, renv state, non-R steps and models **(changed Must)**; manifests are gitignored, with a copy per tag in `artefact/manifests/` **(new Must)**; manifests and logs are exempt from byte-identical rebuilds. New subsection "Non-R steps and pretrained models": hashed lock **(new Must)**, header and reproduce.sh reach **(new Must)**, pinned model revision **(new Must)**, weights outside the repo with a register row **(new Must)**, all recorded in the manifest **(new Must)**.
  - Tests and upkeep: a test that every relative link resolves **(new Must)**; more repo-health checks; styler with `strict = FALSE` in the pre-report routine.
- **R Code Style Guide:**
  - Headers: function files whose functions write carry an Outputs line; test helper and setup files point to the brief; test-\*.R and generated files carry no header **(changed Must)**; a `Sourced by:` list is prose; a figure function file names its own path in a literal.
  - Formatting: styler with `strict = FALSE`, which keeps the two-space inline comments **(changed Must)**; the template `.lintr` turns off `object_usage_linter` **(changed Must)**; component packages, never `library(tidyverse)` **(new Must)**.
  - Data safety: quantile levels keyed on `sprintf("%.3f", ...)` **(changed Must)**; `week_end` derived from a source's week label, its own date kept only for a counted check **(new Must)**; agreement rates written to a check table **(changed Must)**; prose-only reference facts go into a `data/reference/` lookup **(changed Must)**; shared source constants in `reference.R` **(changed Must)**; `newest_snapshot()` renamed `newest_vintage()`; `read_as_of()` takes a default.
  - Console and plots: long cli templates as `paste0()` of literals or `c()` lines; isolated points drawn with `geom_point()` and counted **(new Must)**; unitless relative measures may share an axis; a cairo png device when ragg is not locked.
- **Templates:** new `plan_objective.md`, `open_questions.md`, `test-repo-health.R`, `Rprofile` and `lintr`; the brief gains "Objectives and status", a grouped configuration row and References; the part page gains a Status line and an optional outputs-by-question table; the data register gains manifests, a frozen-extract row, a reference row and a model-weights row; the function-file header gains an optional Outputs line; `.gitignore` ignores run manifests and Python environments; `.Renviron.example` treats empty as unset and adds `MODEL_DIR`; `GUIDES.md` links v1.1 and an optional `guide_feedback.md`.

Projects: add `documentation/open_questions.md` and a `plan_<objective>.md` per objective, and move any drafted plan, option or recommendation the owner did not ask for out of the repo; label the decisions.md entries; tag the protocol before the first result; gitignore the run manifests and write one per entry point; set renv snapshot type "implicit", warn when renv is inactive, and take the P3M codename from the machine; add a manifest.json to each script-written vintage and verify it on load; replace `Sys.getenv(x, unset = d)` with a helper that treats empty as unset; copy `templates/lintr` and run styler with `strict = FALSE`; add the link test; rename `newest_snapshot()` to `newest_vintage()` (an alias may stay until each call site is next touched); lock any Python step and pin each model revision. Then update the version, links and date in `GUIDES.md`, and drop Known departures that v1.1 now allows.

## v1.0 (2026-11-18)

First release, after one review round in comments.

- **R Code Style Guide:** how code inside `.R` files and Quarto chunks reads. Covers the header block (Purpose, Inputs, Outputs, Run, Part), the `+++` banners and `|-` markers, comments that say why, naming with units, tidyverse grammar, functions with `params` first, `cli` console output for supervising a run, data safety, plots, formatting, habits to avoid, and a read-through before every commit.
- **Repo Practice Guide:** how a project is built and kept healthy. Covers the documentation hierarchy (brief, `PART_<folder>.md` pages, script headers), the folder layout, inputs and outputs, one-command runs, reproducibility, tests, git hygiene with private data, and routine upkeep.
- **Templates:** project brief, part page, data register, guides pointer, script and function-file headers, `.gitignore` and `.Renviron.example`.
- **Licence:** CC BY 4.0 for the guides, templates and diagram.

Projects: add `documentation/guides/GUIDES.md` from [templates/GUIDES.md](templates/GUIDES.md), record the version and the date checked, and list any lasting departures there.
